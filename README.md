# Serious Trading

A 2D top-down, multiplayer **prediction-market trading floor**. Players walk a pixel-art exchange, step into trading pits and place limit orders on event contracts in real time, against each other and a market-making bot. The whole backend (matching engine, accounts, game state) runs inside **SpacetimeDB**.

Production domain: **[serioustrading.ink](https://serioustrading.ink)** (Vercel + SpacetimeDB Maincloud).

---

## Features

- **Trading floor (Phaser 4):** full-screen pixel-art hall with a walkable 20×11 grid, a central trading pit, pits the instructor deploys for extra markets, an LED ticker, speech bubbles for fills and a live minimap.
- **Login:** pick a unique name and one of two avatars (Serious Trader #1 / #2) before entering the floor.
- **Central limit order book:** price-time priority, integer cents (1-99¢), `1 YES + 1 NO = $1.00`. Bids/asks escrow cash when placed, there is no self-matching, and price improvements are refunded.
- **Market maker:** a bot quotes a two-sided ladder around fair value and snipes mispricings. It trades under the module's own identity.
- **Instructor "god mode" (`/instructor`):** passcode-gated dashboard (no Phaser). Deploy markets onto the floor, edit them (with a confirm step that wipes and refunds resting orders), reveal clues, broadcast breaking news, resolve markets, and watch a live net-worth leaderboard. **End Round** freezes the floor and reveals the podium to students.
- **Presence:** when a player disconnects, their avatar stays for 2 minutes and is then removed from the map. Their resting orders remain in the book.

## Running locally

Prerequisites: Node.js 18+ and the [SpacetimeDB CLI](https://spacetimedb.com/install).

```bash
npm install
spacetime start                 # local SpacetimeDB on :3000 (separate terminal)
npm run server:publish          # publish the module as "serious-trading-local" (wipes local data)
npm run dev                     # http://localhost:5173  (instructor: /instructor)
```

The default instructor passcode is `CALHACKS13`; change it from the dashboard.

After changing the module, run `npm run spacetime:generate` to refresh `src/module_bindings`.

## Environment

The client reads two Vite variables:

| Variable | `.env.development` | `.env.production` |
|---|---|---|
| `VITE_SPACETIMEDB_URI` | `ws://localhost:3000` | `wss://maincloud.spacetimedb.com` |
| `VITE_SPACETIMEDB_NAME` | `serious-trading-local` | `serious-trading` |

Production builds fail unless the URI is a `wss://` address and a database name is set, so a deployment can never fall back to localhost.

## Deploying

1. **Publish the module to Maincloud** (once, then whenever the module changes):
   ```bash
   spacetime login
   npm run server:publish:cloud   # publishes as "serious-trading"
   ```
2. **Deploy the frontend to Vercel:** import the repo. `vercel.json` sets the build (`npm run build`, output `dist`) and rewrites every route to `index.html` so `/instructor` works. Vercel builds in production mode and picks up `.env.production`; variables set in the Vercel dashboard override it.
3. **Domain:** add `serioustrading.ink` to the Vercel project and point its DNS at Vercel.
